# Tutorial run — KJV / Qur'an / Talmud, web-search on vs. off — 2026-10-11

The committed evidence for Spec 8 (issue #8). Generated by the commands in the
repo-root `TUTORIAL.md` with `--seed 20261011`; copyright-audited origin-clean
(public-domain / open original-language corpora only). See `summary.md` for the
accuracy table, the panel composition, and token totals.

- **Task / scope:** 100 seeded `retrieve_quote` questions, balanced across three
  traditions and three scripts — **34 Judaism** (Talmud Bavli, Aramaic original, `he`),
  **33 Sunni Islam** (the Qur'an, Uthmani QUL, `ar`), **33 Protestant Christian** (the
  Bible, KJV, `en`); expected text is 34 Hebrew / 33 Arabic / 33 Latin. Question-set
  digest `37eb58400fdf4ea9`, corpus hash `ed3f05dcf703e2e3`.
- **Panel — 2 models run both ways (web search on / off) = 4 entries:**
  `claude-opus-5-5` and `claude-haiku-5-5`, each with the Anthropic server-side web
  search tool **enabled** (`-search`) and **disabled**. Tool version
  `web_search_20250305`, `max_uses: 5` per turn. The tools setting is encoded into each
  entry's panel identity (`[web_search]` / `[no-tools]`) so on/off never collapse into
  one standings row and never collide with the earlier first-run `claude-haiku-5-5` row.
- **Web-search activity:** the tool was *available* on all 200 search-on cells and the
  model *chose* to invoke it on 93 — opus-search searched on 34 cells (131 requests),
  haiku-search on 59 cells (95 requests); 226 web-search requests in all. Token totals
  are in `summary.md`.
- **Unpriced by design:** web search bills per request (not captured in input/output
  tokens), so pricing the panel would understate true cost — `summary.json` carries
  token totals only, no `cost_usd`.

## The contrast — what the run actually shows

The benchmark exists to compare parametric recall (tools off) against tool-assisted
retrieval (tools on). The honest result here is that **web search did not improve
strict-reference accuracy, and slightly reduced it**:

| model        | overall | Judaism | Protestant Christian | Sunni Islam |
|--------------|---------|---------|----------------------|-------------|
| opus         | 66%     | 0%      | 100%                 | 100%        |
| opus-search  | 66%     | 3%      | 100%                 | 97%         |
| haiku        | 47%     | 0%      | 85%                  | 58%         |
| haiku-search | 40%     | 0%      | 85%                  | 36%         |

Two things drive this, and both are the scoring contract working as designed rather
than a defect:

- **Orthographic variance on the Qur'an.** When the tool fires, it tends to retrieve the
  Arabic text in a slightly different vocalisation/orthography than the Uthmani (QUL)
  reference (e.g. different placement of small marks, explicit vs. dagger alef). The
  non-Latin normalisation (Spec 8 Phase 1) folds diacritics and tatweel, but it
  deliberately does **not** rewrite letter choices, so a correct-but-differently-spelled
  retrieval misses the exact Uthmani reference and scores `correct = 0`. The headline
  `correct` is whole-string normalised equality; `token_f1` in `scores.jsonl` shows these
  near-misses are close, not fabrications.
- **Talmud Aramaic recall floor.** All four entries score ~0% on the Aramaic Talmud:
  the models either abstain or answer in English about the passage rather than
  reproducing the Aramaic original. Web search does not lift this.

The opus overall tie (66% vs. 66%) includes one search-on item that flipped right→wrong
*without* invoking search (answered from memory) — i.e. ordinary sampling variation, not
a web-search effect. The contrast is readable from the committed artifacts: per-entry and
per-tradition accuracy in `summary.md`, and the discriminating `exact` / `normalized` /
`token_f1` in `scores.jsonl` (and the viewer error explorer).

## Reading the scores (important caveat)

The `retrieve_quote` headline is deliberately strict: the whole answer must be the exact
reference text and **nothing else**. `exact` / `normalized` / `token_f1` are reported
alongside so the strictness is visible — a low headline with high `token_f1` is a correct
quote with a wrapper or an orthographic variant, not wrong scripture.

- **Model answers are committed as collected.** This run does **not** apply a manual
  copyright-clearance / redaction pass over the search-on answers: the maintainers treat
  incidentally-retrieved copyrighted text appearing in a model's answer as fair use for
  academic research, and answers are never truncated or edited (the explorer must show
  them verbatim). The standard automated audit still gates every commit.
- **Automated audit scope.** `audit` ran **origin-only** here: its content layer
  fingerprints restricted unit texts only when the held-back restricted payloads are
  present locally, and this run uses no restricted source. Origin is the enforceable
  proxy in a clone / CI, where restricted payloads are never committed.

## Reproducing

Follow `TUTORIAL.md` (same `--seed 20261011`, `--per-task 100`, the three standardized
corpora, and `configs/models.example.yaml`). Collection requires `ANTHROPIC_API_KEY` in
the environment and incurs per-request web-search cost; scoring and the viewer are free
and deterministic over the committed `answers.jsonl`.
