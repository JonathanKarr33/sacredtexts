## Issue 1 (blocking) — a *repeated* correct citation is misread as a hedge

`_single_citation_correct` (score.py:115-121) counts candidates as a set of normalized spans **including their greedy prefix words**, so the same citation stated twice yields two distinct spans. Verified against the real code:

| answer | expected | `n_candidates` | `correct` |
|---|---|---|---|
| `The citation is John 3:16 (John 3:16).` | `John 3:16` | 2 | **0** ❌ |
| `This passage is Jude 1:3. Jude 1:3 warns believers.` | `Jude 1:3` | 2 | **0** ❌ |
| `Rerum Novarum, para. 5. Yes, Rerum Novarum, para. 5.` | `Rerum Novarum, para. 5` | 2 | **0** ❌ |
| `Sahih al-Bukhari 1. That is Sahih al-Bukhari 1.` | `Sahih al-Bukhari 1` | 2 | **0** ❌ |

The candidate set is literally `{'this is jude 1 3', 'indeed jude 1 3'}` — one citation, two prefixes. All three shapes are affected.

This is the inverse of the hole iter 4 fixed, and it violates this phase's own acceptance criterion ("a single correct citation scores 1") and the spec's contract wording: *"the **single** extracted citation equals ground truth; **multi-candidate** answers score 0."* A citation repeated is one candidate, not a hedge. The direction matters for the paper: it **understates** model accuracy on `cite_passage`/`identify_source`, which on a provenance-honesty benchmark overstates the problem the paper reports — the spec's own risk table rates "strict match unfairly punishes verbose models" High probability, and unlike `retrieve_quote` these tasks have no second tier to fall back on. The `_ANSWER_ONLY` prompt instruction reduces the rate but cannot be the defense: a prompt-compliant model wouldn't hedge either, yet the anti-hedge machinery exists anyway.

**Verified fix** — collapse all spans that assert the expected citation into one candidate, in `_single_citation_correct`:

```python
cands = _citation_candidates(answer, expected_citation)
# spans asserting the EXPECTED citation are ONE candidate however often the model
# repeats it ("It is Jude 1:3. Jude 1:3 warns…") — repetition is not a hedge
ne = normalize(expected_citation)
bnd = re.compile(r"(?<!\w)" + re.escape(ne) + r"(?!\w)")
matching = {c for c in cands if bnd.search(c)}
others = cands - matching
n = (1 if matching else 0) + len(others)
if n > 1:
    return 0, n
return int(_bounded_equal(answer, expected_citation)), n
```

I applied this to a `/tmp` copy and ran **16 cases: 16/16** — all four repeats above → 1, every existing hedge/near-miss/incidental case unchanged (same-book hedge n=3→0, cross-book n=3→0, lowercase n=2→0, num n=2→0, both para hedges n=2→0, `Jude 1:30`→0, wrong citation→0). The full `test_score.py` (23 tests) passes against the patched copy with no edits to the tests. Please add both-direction regression tests (repeat-correct → 1 for colon/para/num, hedge → 0) so this branch doesn't regress the way the para branch did.
