### Issues

**1. Token/cost totals are never computed or committed (plan deliverable + spec criterion).**
Plan Phase 8 design decision: *"Usage/cost: totals from `collect`'s recorded `usage` tokens … report token totals"*; deliverable: *"token (and optional cost) totals computed"*; spec success criterion: *"commit the summary + artifacts as evidence, **with usage/cost totals computed from the data**."*

`usage` is recorded per row (`{"in":37,"out":21,"provider":"Novita"}`), but nothing aggregates it: `summary.json` has only `models` and `by_tradition`; `grep usage` in `score.py` → nothing; `cli.py` → nothing; no mention in `TUTORIAL.md`, `summary.md`, or `pipelines/README.md`. I computed it in one line from the committed data:

```
claude-haiku   in   5,810  out  41,140
gpt-oss-20b    in  10,080  out  80,188
gemma-3-4b     in   4,615  out   6,252
llama-3.1-8b   in   4,715  out   6,551
TOTAL          in  25,220  out 134,131   (400 cells)
```

That it's a one-liner is the point — the deliverable is cheap and currently absent. Smallest honest fix: add a `usage` block to `summary.json`/`summary.md` in `score` (per-model `in`/`out` + totals, plus optional cost when the run config supplies prices, per the plan's "do not invent prices").

**2. TUTORIAL step 6 crashes for a reader without API keys.**
Step 6 passes `--config configs/models.yaml`, which only exists after step 5 (the paid step). A keyless reader — exactly the demo path the spec requires (*"Demo-able … no gitignored restricted data required"*, and the committed answers exist precisely so collect can be skipped) — gets an unhandled traceback:

```
FileNotFoundError: [Errno 2] No such file or directory: 'configs/models.yaml'
  (sacredbench/config.py:51, load_config)
```

I confirmed the keyless path works fine if you just drop `--questions`/`--config` — identical `scores.jsonl`, same summary table. So this is a one-line TUTORIAL fix ("no keys? skip step 5; drop `--questions/--config` and score the committed `answers.jsonl`"). Optionally also wrap `load_config`'s open so a missing panel is a clean fail-fast message rather than a traceback.
