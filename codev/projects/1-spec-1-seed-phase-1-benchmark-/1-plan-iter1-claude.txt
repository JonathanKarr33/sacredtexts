## Issues

**1. `source.yaml` schema can't express the committed layout (blocking Phase 1↔2).** Phase 1 specifies a *single flat record* (`tradition[]`, `work`, `version`, `language`, `document_type`, `converter`, `license`) and "one `texts/raw/<source>/source.yaml` per landed source (7 traditions)". The on-disk tree is tradition-dir-per-folder holding *many* works/versions: `Protestant Christian/` = kjv+asv+web (3 versions), `Sunni Islam/` = Quran file **plus** a 9-collection hadith dir, `Judaism/Talmud Bavli/` = ~37 tractates × 2 languages ≈ 74 documents, `encyclicals/` = 211 documents, LDS = 5 works. Seven single-record YAMLs cannot describe ~300 `(work, version, language)` targets. The plan must pick: a `targets: [{glob, converter, work, version, language, document_type}]` list, or converters that derive metadata from the data (Talmud files carry `title`/`versionTitle`/`language`; encyclicals carry `title`). This also decides Phase 2's dispatch contract — needed, because today's signatures are incompatible (`convert_nabre(paths, tradition, version, work, language, source_url)` vs `convert_encyclicals(paths, tradition)`). State the common interface, e.g. `fn(paths, entry) -> list[Document]`.

**2. Talmud: HTML markup + daf offset + empty sections — none of it named.** Verified on `Taanit - en …json`: `sectionNames: ['Daf','Line']`, `text` is 61 sections, **sections 0 and 1 are empty** (tractates start at 2a, so index→daf is `i//2+1` + `a/b`), and line text is `"<strong>MISHNA:</strong> <b>From when,</b> …"`. Two consequences: (a) citation derivation must handle the offset and skip empties — exactly the lessons-critical "derive from the real data" trap; (b) `entries[].text` is spec'd as EXACT TEXT, so if tags survive, `retrieve_quote`/`complete_unit` normalized-exact is **unachievable for every Talmud item** and `token_f1` is polluted (`normalize()` at `score.py:42` strips punctuation but leaves `strong`/`b`/`i` as tokens). Decide where markup is stripped — Phase 2 converter or Phase 5 normalizer. Also: the en Talmud files declare `"license": "CC-BY-NC"` internally; worth carrying into `source.yaml` deliberately.

**3. Non-Latin normalization unaddressed, and Phase 7's corpus scope unstated.** Quran (Uthmani, full tashkeel) and all 9 hadith collections are Arabic-only; Talmud `he` is Aramaic. `normalize()` is Latin-centric (quote/dash folding + casefold). Phase 5 says nothing about alef/yeh folding, tatweel, tashkeel or nikud. Phase 7 says "~100 seeded `retrieve_quote` questions" without naming which corpora — if Arabic/Hebrew is in scope, Phase 5 needs a normalization rule; if the first run is English-only (defensible narrowing), say so explicitly, since it determines Phase 5's scope.

**4. Duplicate `(work, version, language)` across traditions.** The LDS set includes `new-testament-reference-KJV-ben-crowder.json`; I diffed John 3:16 against `Protestant Christian/kjv.json` — byte-identical. So two documents become (The Bible, KJV, en) with different `tradition` lists. Phase 3 assembles per work/version and will merge them (tradition union is probably right per the spec's many-to-many intent — state it); Phase 4's "≥2 converted versions" gate and Phase 5's per-tradition `n` both get distorted if the same verse yields questions twice. Related and missing: the spec's overlap exclusion covers only `verify_source` negatives, but `identify_version` has the same hazard (a verse identical in KJV and ASV has two correct answers, one scored ground truth). Either exclude or explicitly accept as noise.

**5. `runs/` is gitignored — Phases 6 and 7 both commit/read run artifacts.** `.gitignore` line `runs/`; Phase 7 says "Commit the evidence under `runs/<dated>/`". No phase lists a `.gitignore` change. Also `configs/models.yaml` is gitignored with `configs/models.example.yaml` committed; Phase 7 puts the run config "under `pipelines/`" — reconcile with the existing `configs/` convention.

**6. Phase 7's live run exercises only the happy path. Add a resume-semantics test behind a fake provider (keeping the live smoke for the real path, per the mock-boundary lesson).

**7. No price data for Phase 7's "usage/cost totals".** `collect.py:58-68` records `usage` tokens, but `ModelSpec` (`config.py:36`) has no price fields and `grep -i price|cost` finds nothing. Either add per-model pricing to the run config or scope Phase 7's deliverable to token totals.

**8. How does `generate` know a standardized doc is restricted?** `Document` (`schema.py:52`) has no `license`, and the interchange format is spec'd verbatim.
