### Findings (none blocking)

1. **Hadith citations are a positional index, not a verified canonical reference — write this down now.** `idInBook` is an int, strictly contiguous `1..N` in all nine collections (I checked every file). Bukhari ends at **7277**, not sunnah.com's 7563 reference ceiling — so `Sahih al-Bukhari 5000` in this corpus is not demonstrably the hadith the world calls Bukhari 5000 (7277 is close to the often-cited 7275-with-repetition Arabic print count). Hadith 1 *does* match canonical Bukhari 1 (I verified the "actions are by intentions / migration" text), so the head aligns and the tail is unverified. The export carries no canonical-number field (`id`/`idInBook` both positional, `bookId ≡ 1`, 97 `chapterId`s), so **the converter cannot do better** — this is a documentation duty, not a code bug. In a benchmark whose whole point is provenance honesty, a citation scheme of unverified provenance deserves a line in the converter docstring and in `Sunni Islam/source.yaml` `notes`, plus a Phase 5 flag. Plan-aligned ("citation from collection + number"), hence a comment.
2. **The iter-1 rebuttal's stated basis for the `idInBook` type guard is factually wrong.** It says "in the real data `idInBook` is a string, so an int-only check would be wrong" — all nine collections are ints. The permissive `(str, int)` guard is harmless, but the recorded reasoning is false and will mislead whoever reads it next. It also accepts `"12 "` or `"3-4"` straight into a citation; int-or-digit-string would be more faithful to the data.
3. **`versionTitle` isn't cross-checked, only `language`.** The language guard catches an en/he mix-up but not a *different same-language edition* merged under the wrong version label (e.g. a Sefaria community English translation would pass). The Vocalized Aramaic variant is excluded by a tightened glob and only errors today because its text happens to conflict with standard Shevuot. Since the catalogue `version` now equals `versionTitle` verbatim, the symmetric guard is two lines.
4. **`_clean_markup` ordering is latently unsafe**: tags are stripped *before* `html.unescape`, so a source `&lt;b&gt;` becomes a literal `<b>` in stored text. Absent from the real data (verified), so latent only — unescape-then-strip would be strictly safer.
5. **125 Malik hadiths (6.3% of 1,985) and 207 Talmud lines are dropped silently.** Dropping is correct; deferring the "skipped N" echo to Phase 8 is defensible, but it's a 3-line `typer.echo` and the project's fail-loudly norm argues for now — a future converter bug that empties units would be invisible.
6. **Docstring drift**: `convert.py`'s "Registered converters" list still names only `bible_flat`/`lds_nested`/`encyclicals`/`nabre`; this phase's three are missing from the list that claims to enumerate the registry.
