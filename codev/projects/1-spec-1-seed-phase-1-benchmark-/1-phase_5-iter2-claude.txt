## Remaining observations (all non-blocking)

**1. The new dedup guard silently under-delivers the quota.** Dedup runs *after* sampling (`generate.py:281-288`), so colliding shards shrink the emitted set below quota with no error. Verified read-only with two shards sharing `(work, version, language, citation, text)`, `per_task=5`:

```
seed 1 {'retrieve_quote': 5, 'cite_passage': 4, ...}
seed 2 {'retrieve_quote': 3, 'cite_passage': 4, ...}   # 40% short, silent
```

`test_duplicate_ids_from_colliding_shards_deduped` only asserts id uniqueness, so it doesn't pin the count. This contradicts the phase's own "configurable quotas" deliverable and the project's fail-fast rule — and Phase 8 wants *exactly* ~100 `retrieve_quote`. It's latent today (LDS KJV carries a distinct version label, OT/NT merge, encyclical dups are excluded by `_is_canonical_citation`), so not blocking. The small fix is to dedup the **pool** on `(work, version, language, citation, text)` before `_balanced_sample`, so the quota is met from distinct content; failing that, raise when dedup drops anything.

**2. The attributed (wrong) work of a `verify_source` negative isn't recorded.** `_build` puts `neg_work` only into the prompt string; `expected` carries `answer`/`true_work` and `source.work` is the *true* work. The artifact therefore can't be audited for which false premise was asserted without re-parsing prose — and the test has to do exactly that (`q.prompt.split(" from ", 1)[1].split("?")[0]`), which would mis-parse any work title containing " from " or "?" and could go quietly wrong. Adding `expected["attributed_work"] = neg_work` fixes both.

**3. `tasks` is not in the manifest.** The rebuttal says `--tasks` was threaded "into both `generate()` and `build_manifest`", but `build_manifest`'s signature is `(docs, questions, seed, per_task, negatives_share, quotas)` — no `tasks`. In practice the run is still reproducible (`tasks_by_count` plus `quotas` recovers which tasks consumed the RNG, since both the task-filter and the `quota<=0` path `continue` before sampling), so this is cosmetic — but for an auditable benchmark manifest, recording the requested subset is one line.

**4. Ambiguity-emptied `identify_version` is skipped silently.** `continue` at `:251` is the right behavior (claude #4), but it emits no warning, unlike the CLI's single-work `verify_source` warning. Also note the boundary just moved: pool `0` skips, pool `1` with `quota 10` still aborts the *whole* run via `_balanced_sample`. Defensible as fail-fast, but worth a line in the error telling the user `--quota identify_version=N` is the escape hatch.

**5. `_existing` KeyErrors on a malformed row.** `d["question_id"]`/`d["model_id"]` are unguarded (`collect.py:43-44`), and `KeyError` isn't in `main()`'s exit-2 tuple, so a truncated/foreign answers file gives a raw traceback rather than the clean refusal message the rest of the path produces.

Out of scope and correctly deferred: `score.py`'s lossy `round(accuracy * n)` `_overall` and the tradition dimension (Phase 6 deliverables); `score` comparing the digest against the manifest rather than just internal consistency (the plan only asked that `score` validate it).
