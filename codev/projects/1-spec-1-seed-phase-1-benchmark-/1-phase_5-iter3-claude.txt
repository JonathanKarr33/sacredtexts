## Findings (none blocking)

**1. `identify_version` on the live corpus is dominated by near-duplicate-edition items.** The expected-version distribution of my 20-item run was `KJV (LDS 2013 edition): 10, ASV: 5, WEB: 5` — **zero** plain KJV. The exact-text exclusion removes every verse the two KJV editions share, which leaves *precisely* the orthographic variants, and those get selected preferentially. Measured with `difflib`: the four LDS items I inspected differ from Protestant KJV at the same citation by one word (`marvellously`/`marvelously`, `Ebed-melech`/`Ebedmelech`) — similarity 0.989–0.998. Under Phase 6's label exact/normalized match these are unanswerable by construction and will score 0 regardless of model skill. The implementation matches the spec's stated exclusion rule exactly, and Phase 8's run is `retrieve_quote`-only, so committed evidence isn't affected — but before any `identify_version` number is reported, consider gating the task to versions within one source, or adding a near-duplicate (similarity-threshold) exclusion.

**2. The RNG is shared sequentially across tasks, so a task subset shifts the other tasks' samples.** Verified: `generate(docs, seed=11, tasks=("retrieve_quote",))` ≠ the `retrieve_quote` slice of the full run at the same seed. (Changing a *quota* is stable, since `shuffle` consumes the same entropy regardless.) Determinism per fixed config holds and `tasks_requested` is in the manifest, so this is not a contract break — but seeding per task (`Random(f"{seed}:{task}")`) would make a subset run a genuine subset, which is handy when Phase 8 regenerates at a different task mix.

**3. Small ones.** `--quota task=-5` silently skips the task (`quota <= 0: continue`) rather than erroring, and a `--quota` for a task excluded by `--tasks` is ignored silently. `int(quota * negatives_share)` truncates (quota 5 at 0.5 → 2 = 40%). A foreign/torn `answers.jsonl` row raises `KeyError`/`JSONDecodeError` from `_existing` rather than `CollectError` — fail-loud, but less legible than the adjacent guards. An `identify_version` pool of 0 is skipped while a pool of 1-below-quota aborts the entire run; the asymmetry is defensible per the plan's fail-fast rule, just worth a comment in the code.

I also note that iteration 1 and 2's blockers (digest content coverage, fail-open digests, negative-ratio guarantee, unreachable `quotas` CLI surface, input-order-dependent balancing, probabilistic ambiguity test, post-sample dedup under-delivery) are all genuinely fixed in code and covered by tests — I checked each rather than taking the rebuttal's word for it.
