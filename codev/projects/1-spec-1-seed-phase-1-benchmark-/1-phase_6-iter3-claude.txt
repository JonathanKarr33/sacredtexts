### Issue 1 (blocking) — the iter-2 `_NUM_CITE` fix regressed correct single-citation answers

`_NUM_CITE` (score.py:88) was added in iter 2 to catch hadith hedges, but it is applied to *every* task regardless of the expected citation's shape, so it fires on ordinary prose containing "Capitalized word + number". Verified against the real code:

| answer | expected | `n_candidates` | `correct` |
|---|---|---|---|
| `The citation is Jude 1:3 (ASV 1901).` | `Jude 1:3` | 2 (`asv 1901`, `jude 1 3`) | **0** ❌ |
| `The quote is from Jude 1:3. It appears in Chapter 1.` | `Jude 1:3` | 2 (`chapter 1`, `jude 1 3`) | **0** ❌ |

A single, *correct*, unhedged citation scores 0 because an incidental version year or "Chapter 1" is counted as a second candidate. This violates this phase's own acceptance criterion — "a single correct citation scores 1" — and it is the mirror image of the error iter 2 was fixing: the veto now over-triggers. `(ASV 1901)` is a realistic shape precisely because the corpus labels versions that way.

### Issue 2 (blocking, same fix) — the all-lowercase hedge still scores 1

Raised by claude in iter 2 (comment C) and **neither fixed nor disputed** — the iter-2 rebuttal summarized the remaining claude notes as only word-order and Arabic normalization, so this one was dropped silently. Verified it is still live:

- `"it could be john 1:1 or genesis 1:1"` vs `John 1:1` → candidates `{'1 1'}` (prefix requires `[A-Z0-9]`, so both collapse) → **`correct=1`** ❌
- `"Perhaps sahih al-bukhari 1, or sahih muslim 2"` vs `Sahih al-Bukhari 1` → 0 candidates → **`correct=1`** ❌

### Suggested fix (two lines, verified)

Make the prefix character class case-insensitive **and** choose the extractor by the *expected* citation's shape rather than unioning all three. I simulated exactly this in `/tmp` against all 12 cases — every existing test expectation plus all three holes:

```python
COLON = re.compile(r"(?:[A-Za-z0-9][^\s,:]*\s+){0,8}\d+[ab]?\s*:\s*\d+")
PARA  = re.compile(r"(?:[A-Za-z0-9][^\s,]*,?\s+){0,8}[Pp]ara\.?\s*\d+")
NUM   = re.compile(r"(?:[A-Za-z][^\s,:]*\s+){1,8}\d+(?![\d:ab])")

def _shape_rx(expected):          # shape of GROUND TRUTH decides the candidate class
    if re.search(r"\d\s*:\s*\d", expected): return COLON
    if re.search(r"[Pp]ara", expected):     return PARA
    return NUM
```

Result: `ALL PASS` — the three hedges above now score 0, `Jude 1:3 (ASV 1901)` and `Chapter 1` score 1, and every currently-passing case (cross-book hedge, disjunction, `Jude 1:30` near-miss, `Rerum Novarum, para. 5`, single hadith, hadith hedge) is unchanged. Please add the three cases above as tests so neither direction regresses again.
