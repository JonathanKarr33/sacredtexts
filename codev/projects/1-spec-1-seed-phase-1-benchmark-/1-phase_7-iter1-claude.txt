## The one real gap: nothing reads run artifacts

`LocalResultsPage.tsx` imports `sampleSummary` / `sampleScoresJsonl` / `sampleAnswersJsonl` as compiled-in TS constants. There is no `fetch`, no file input, no dev-served path — the page can only ever render the baked fixture.

That misses the spec's wording for this deliverable: *"served by a local dev server **reading the run artifacts** (committed or local `runs/`)"*, and the plan's Phase 7 deliverable *"showing run summary + per-question scores **from local artifacts**"*. It also makes two existing claims non-actionable:

- `apps/viewer/README.md:12` — "Pointing it at a real run under `runs/` is the TUTORIAL's final step." There is no mechanism to point it anywhere.
- Plan Phase 8 deliverable — "The minimal viewer renders this committed run." Phase 8 touches no viewer files, so the loader has to land here or the loop closes on a synthetic fixture. Note `runs/` is gitignored (`.gitignore:33`), so the loader and the evidence path need to agree.

Minimal remedy (keep it small — this is loop-closure, not polish): have the page `fetch` three artifact URLs from a configurable base (e.g. `?run=/runs/<id>` with a dev-only vite middleware or `publicDir`/symlink exposing the repo's `runs/`), and fall back to the committed sample when the fetch 404s. A file-picker (`<input type="file" multiple>`) is an even cheaper variant that needs zero server config and works in `preview` too. Then test *that* loader against fixture JSON/JSONL files, not just the in-memory constants.

## Smaller notes (not blocking)

1. `parseJsonl` (`localResults.ts:56`) throws a bare `SyntaxError` with no file/line context. Real `answers.jsonl` from an interrupted `collect` can have a truncated final line — worth naming the line number once you're reading real files.
2. `parseSummary` throws on a missing `models` key and the page has no boundary. Harmless with a static import; add an error state when the loader lands (`ErrorBoundary.tsx` already exists in the app).
3. `expectedText` (`:64`) returns the first matching key in order `text, citation, version, answer, work` — so for `identify_source` (expected `{work, citation}`) it shows only the citation and silently drops `work`. Fine for Phase 8's `retrieve_quote`-only run; will under-report once the other tasks are generated.
4. `by_tradition` is parsed into `Summary` but never rendered. Not required by this phase (spec asks for summary + per-question scores), just dead weight for now — or a cheap win, since `score.py` already renders that breakdown in markdown.
5. `src/local/sample.ts` lives under `src`, so the fixture and `/local-results` ship in any production build. Not a violation of "no deploy," but worth knowing if the Spec 2 SPA ever deploys from this tree.
