## Findings (none blocking)

**1. The copyright gate silently disables itself (the one I'd fix now).** `_catalogue_or_empty` (cli.py:28) returns `[]` whenever discovery fails with a message containing `"not found"`/`"no source.yaml"`. I reproduced the consequence: with `--raw-root <nonexistent>`, `convert` happily proceeded to convert a **restricted** payload with no warning at all. The same happens if a user runs from a subdirectory (default `raw_root` is the relative `texts/raw`). That's a silent fallback on a High-impact risk, contrary to the repo's own fail-fast principle. Cheap fixes: (a) give the loader a distinct `CatalogueMissing(CatalogueError)` subclass instead of substring-sniffing the message, and (b) fail if `--raw-root` was passed explicitly and doesn't exist, or at minimum emit a loud stderr warning that the license gate is inactive.

**2. The CLI wiring of the gate is untested.** `test_catalogue.py` covers `select_targets` / `filter_standardized_paths` at library level, but the phase's acceptance criterion is CLI-level behavior. A `CliRunner` test for `convert` refusal + `generate` filtering would lock in what I had to verify by hand. Phase 2 touches this code, so now is cheap.

**3. `converter` names are unvalidated against `CONVERTERS`.** Reasonable for this phase (bodies land in 2/3), but note `Greek Orthodox` declares `converter: tlg` and no plan phase ships a `tlg` converter — so `--include-restricted` with a local TLG copy will fail late. Suggest a registry cross-check over *selected* targets in Phase 2, and an explicit decision on `tlg`.

**4. Judaism target uses `language: mul`**, which breaks the module's own "each target is one `(work, version, language)` unit" invariant and puts en and he docs in the *same* `standardized_dir` slug. Both are `open`, so license recovery is unaffected — but the Phase 8 English-only run can't select by path, and Phase 3's plan text says en/he are separate versions. Either split into two targets (cheap, keeps the invariant) or document `mul` as a deliberate exception.

**5. Minor**: the two LDS `The Bible` targets share a slug, so Phase 2 must write distinct filenames inside that dir. `license_for_raw_path` re-globs every target per input file (≈22 globs × N inputs) — hoisting a path→license index would help on the 201-file encyclicals run. And `texts/README.md` still says "see the restricted-sources flag in `pipelines/README.md` *once implemented*" — it's implemented now (that file isn't in this PR's scope, but it's a one-line staleness tied to this phase).

The 7-vs-6 tradition-directory count the builder flagged in its thread is a plan-text artifact (NABRE is a target inside Roman Catholic, not its own dir), not a missing deliverable — I agree with the builder's reading.
