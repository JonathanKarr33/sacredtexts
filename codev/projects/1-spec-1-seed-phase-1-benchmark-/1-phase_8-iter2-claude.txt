## Findings (new, not raised in iter-1)

**1. TUTORIAL step 6's keyless command overwrites the committed evidence with a *weaker* summary.** The keyless variant (TUTORIAL.md:93-99) writes to `runs/first-run-2026-10-11/summary.json` and `summary.md` — the committed artifacts. I ran it to `/tmp` and compared: `scores.jsonl` is identical, but the summary is not. In the keyless path `panel = {}` (cli.py:324), so `score.py:339-348` emits `provider: null`, `endpoint: null`, and `models` loses `expected_n`/`missing`. Rendered:

```
| claude-haiku | — | claude-haiku-5-5 | — | — |
```

under the heading *"Panel (committed-artifact proof of the ≥3-model / ≥2-provider bar)"*. So a fresh-clone reader following the tutorial verbatim (a) dirties their tree against the committed evidence, and (b) silently destroys the exact proof iter-2 added — while the table still claims to be that proof. The builder's own iter-2 fresh-clone run must have done this and not noticed the diff.

Cheap fixes, either or both: point the keyless step at a scratch path (`--summary-out /tmp/summary.json …`) so the committed artifact is read, not rewritten; and in `score.py` omit the `panel` block entirely when no provider/endpoint info is available, rather than printing a provenance table full of `—` under a "proof" heading. (A more durable fix for future runs: have `collect` record `provider`/`endpoint` per answer row so the keyless score can reconstruct the panel — but that can't retrofit the already-committed `answers.jsonl`.)

**2. The iter-2 additions have no test coverage.** `grep` for `usage|panel|price` in `pipelines/tests/test_score.py` returns nothing. The `usage` aggregation (score.py:242-252, 315-335) and the `panel` block (339-348) — both added specifically to satisfy a plan deliverable ("token (and optional cost) totals computed") and a spec criterion — are verified only by eyeballing the committed summary. A ~15-line test over two synthetic answer rows (per-model and total in/out, a row with no `usage` key contributing 0, panel passthrough) would make the deliverable a gate rather than an artifact.

**3. The cost branch is unreachable, and the docs say otherwise.** `score.py:326` reads `price_in`/`price_out` from the panel dict, but `cli.py:318-321` only ever sets `provider`/`model`/`endpoint`, and `ModelSpec` (config.py:34-41) has no price fields — so `load_config` silently drops any prices a user puts in `models.yaml`. There is currently **no way** to supply prices, yet `pipelines/README.md:97` and score.py:315-316 tell the reader cost appears "if the run config supplies" them. Either wire prices through (`ModelSpec` → cli panel) or drop the branch and the claim. Low impact (the plan only requires token totals), but it's dead code plus an inaccurate promise.
