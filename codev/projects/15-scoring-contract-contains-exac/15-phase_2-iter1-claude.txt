## Issues (none blocking)

1. **`submetrics_for` silently drops an unrecognised metric key** (`graders.py:103` filters by `_CANONICAL_ORDER`). A future inline grader declaring a key outside that tuple loses its metric from `scores.jsonl` *silently*, and its verdict lambda then `KeyError`s on `score.py`'s hardcoded `computed` dict. That's exactly the trap the phase-5 "add an evaluator" recipe will walk a contributor into, and it violates the project's fail-fast rule. Cheap fix: validate at import that every inline grader's `metric_keys ⊆ _CANONICAL_ORDER` (or raise in `submetrics_for`). Worth doing in phase 3 so the phase-5 recipe can lean on it.
2. **Stale `.get()` tolerance / empty-list hole.** `acc[sm] += metrics.get(sm, 0)` (`score.py:362`) now can't miss, since `sm_keys` derives from the same selection — `metrics[sm]` would fail loudly if that ever drifts. Similarly `score_answer(..., graders=[])` passed explicitly yields `correct=0` with no error, bypassing `resolve_evaluators`' empty check. Both low-probability, both one-liners.
3. **Dead `_SUBMETRICS` rows.** The thread says "`_SUBMETRICS` kept only for `identify_version`", but `score.py:116-120` still carries the `retrieve_quote`/`complete_unit` entries, now unreachable via `_task_submetrics`. Editable-with-no-effect; trim to `identify_version`.
4. **Docstring drift in `graders.py`.** It says values are "computed in `score.py` (keyed by grader name)" — they're a flat 4-primitive dict, not grader-keyed; and it cites an import cycle that doesn't exist (`graders.py` imports nothing from the package), so the function-local imports in `score.py` need no such justification. Phase 5 touches docstrings anyway.
5. **No provenance stamp of the selected graders.** A `scores.jsonl` scored with `--evaluator strict` is indistinguishable from the default one by inspection — `correct` means something different with nothing recorded. Adding `summary["evaluators"]` now would have broken the phase-2 no-op, so deferring was right; phase 3 rewrites the summaries anyway and is the natural place.
6. **Test-quality notes** (non-blocking): in `test_separate_pass_grader_is_expressible_but_not_inline`, `assert "jev" not in DEFAULT_EVALUATORS` is vacuous (the tuple is frozen at import, so it would pass even with `default=True`) — the real paid-never-default guard is `test_default_set_is_the_deterministic_inline_graders`, which is sound. The "merge path" block only mutates a local dict and asserts its own mutation, so it documents the seam rather than covering it. The test also mutates module-global `GRADERS` (restored in `finally`; no xdist in this project, so safe today).

Forward note for phase 4, not a change request: `QuestionList.tsx` hardcodes three metric keys, which are now absent under a subset selection — already in the phase-4 scope.
