## Blockers

**1. The viewer vitest suites pin the numbers you are about to change — and your test gate won't run them.**

`.codev/checks/test.sh` maps `runs/` → the **pipelines** lane. A commit touching only `pipelines/` + `runs/` runs pytest only; vitest never fires. But these read the committed runs as fixtures and will break on main:

| File | Assertion | After rebaseline |
|---|---|---|
| `apps/viewer/src/local/tutorialRun.test.ts:117` | order `["opus","opus-search","haiku","haiku-search"]` | becomes `["opus-search","opus","haiku-search","haiku"]` |
| `…tutorialRun.test.ts:118-119` | `rows[0]=0.66`, `rows[3]=0.4` | `0.74` / `0.47` |
| `…tutorialRun.test.ts:148` | `stats.correct === 40` | `52` |
| `routes/ExplorerPage.test.tsx:152` + the "narrows to the 24 correct answers" test | `24 correct` | `25` |

So there are **nine** affected guards, not four. Phase 1 must enumerate and update these in the same atomic commit (which also makes the dispatcher run vitest). Corollary: the plan's "no viewer change → minimal conflict surface with `aspir-11`" claim is false; flag the viewer test files to the architect for merge coordination.

**2. `first-run` summary.json cannot be regenerated through the CLI — by design.**

`runs/first-run-2026-10-11/answers.jsonl` rows carry **no `panel_fingerprint`** (I checked; `collect.py:46` documents it: "first-run's rows carry a digest but no fingerprint"). So `score --config` raises `ScoreError` on every model id (`cli.py:325-331`), and re-collecting is forbidden. And a keyless `score` drops `panel`/`expected_n`/`missing` entirely — the exact scar in `lessons-critical.md`. Also `configs/models.yaml` is **gitignored**, so neither run's original config exists in-repo.

The plan's mitigation ("regenerate via the guarded `score_file` path; carry panel/usage blocks forward verbatim") is not a procedure. It needs to be spelled out:

- **first-run:** call `score_file()` directly with `panel` reconstructed **from the committed `summary.json`'s own panel block** (prices `None`) and the roster rebuilt from committed `questions.jsonl` × the 4 model ids. Do **not** rebuild it from a YAML config: `cli.py:349` would stamp `claude-haiku-5-5 [no-tools]`, which changes the standings key and **collides with the tutorial's `haiku` row** in cross-run standings (and makes `test_tutorial_run.py:20` `FIRST_RUN_KEY` stale) — the very collision `arch-critical.md` calls a zero-viewer-change property.
- Note the honest diff: first-run's summary will also gain `api_model` (score.py:429) and `generated_at` (score.py:435), neither of which it has today. The acceptance criterion "only accuracy + `generated_at` differ" is wrong as written.
- **tutorial:** fingerprints *are* present (`anthropic|claude-haiku-5-5||`), so a reconstructed `models.yaml` works — but say so, and say that the reconstruction is ephemeral (gitignored), so the rebaseline command must be recorded in the review to be reproducible.

**3. `test_score.py:231` must NOT gain `contains_reference`.**

The plan says "update the two whole-`metrics`-dict equality assertions (`:46`, `:231`) to include `contains_reference`." Line 231 is `identify_version` (`assert ok == {"exact":1,"normalized":1,"correct":1}`).
