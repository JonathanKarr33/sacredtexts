## One real bug

`_with_outcome` (score.py:284) runs `classify_refusal` **unconditionally**, and `classify_refusal` drops the "did-not-deliver" half for `cite_passage` / `identify_source` / `identify_version` (outcomes.py:111, `return True`). So a decline-prefixed but **correct** provenance answer is flipped to refused and its headline is zeroed. Demonstrated:

```
score_answer('identify_source', "I can't verify, but it is from Jude, Jude 1:3.", …)
→ {'work_found': 1, 'citation_found': 1, 'correct': 0, 'outcome': 'refused'}   # correct was 1
```

This contradicts the spec's own conservative rule ("a decline-prefixed answer that still delivers … is an answer, not a refusal"), its success criterion *"Provenance tasks keep their correct/incorrect scoring; they gain only the universal `refused` outcome"*, and its Test Scenario "Provenance untouched". Nothing in `test_score.py` / `test_outcomes.py` covers a hedged-but-correct provenance answer.

Fix is one line in `_with_outcome` — gate on the verdict:

```python
if not metrics["correct"] and classify_refusal(answer, task, expected):
```

This is **provably a no-op on the committed evidence**: it can only remove cells with `correct == 1` from the refused set, and `test_outcome_exclusive_and_refused_keeps_submetrics` already asserts every refused row has `correct == 0`. So no third rebaseline — just the fix plus a unit test (hedged-correct `cite_passage` / `identify_source`).
