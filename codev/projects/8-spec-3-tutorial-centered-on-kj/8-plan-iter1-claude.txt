## Defects

**1. Phase 1's Hebrew derivation yields an empty set (significant).** The deliverable says re-derive marks from "the Davidson `he` data." The catalogued canonical Aramaic files contain **zero** codepoints in `U+0591–U+05C7` (checked Taanit: 0 marks in 150KB). Followed literally, Hebrew handling ships as a no-op, and the plan's own acceptance test ("vocalized vs. unvocalized Talmud line") cannot be written from catalogued data. The real fixture source is on disk: `Shevuot - he - William Davidson Edition - Vocalized Aramaic.json` (106,389 marks — `0x5BC`, `0x5B8`, `0x5B0`, `0x5B7`, `0x5C1`…), deliberately *excluded* from the catalogue. Name it as the fixture source, and warn it must not enter the corpus.

**2. The Hebrew risk is asymmetric (significant).** Expected text is unvocalized; the *answer* may be vocalized — especially search-on, fetching Sefaria/Chabad. Un-normalized, that splits the answer into letters → `token_f1`≈0 → **the search-on entry scores artificially lower**, inverting the precise contrast the spec exists to display. Acceptance criteria should assert the asymmetric direction, not just symmetric equality.

**3. "as existing provider tests do" is false (moderate).** There are no provider-seam tests; every mock is at `collect_mod.complete`. `_anthropic` lazily does `import anthropic` *inside* the function, so capturing the `tools` kwarg needs a named technique (`monkeypatch.setitem(sys.modules, "anthropic", …)` or patching `anthropic.Anthropic`).

**4. Tool version is under-determined (moderate).** The SDK exposes **three**: `WebSearchTool20250305Param`, `WebSearchTool20260209Param`, `WebSearchTool20260318Param`. Pick one, record it in the run README (it's part of what the run proves), and set `max_uses` for cost control.

**5. `max_tokens` truncation unaddressed (moderate).** `complete()` raises on empty text and **retries** — each retry is another billed search. At `max_tokens: 1024`, search/citation blocks share the output budget; truncation yields a partial quote scoring 0 on whole-answer equality, again confounding the contrast. Add headroom and a loud `stop_reason == "max_tokens"` check.

**6. Standings collision with first-run (moderate).** first-run's panel is `anthropic\u0000claude-haiku-5-5`. If search-OFF emits an unmarked `claude-haiku-5-5`, it yields the identical key and — being more recent — **replaces** first-run's haiku row. Phase 2's criterion only tests on-vs-off distinctness, which passes anyway. Mark *both* variants; assert non-collision with the committed key.

**7. A stronger Latin regression is free (recommend).** Re-score `runs/first-run-2026-10-11/answers.jsonl` to a **tmp path** and assert equality with the committed `scores.jsonl`. That proves invariance over ~400 real answers vs. a few fixtures — and is safe, never writing over the evidence.

**8. Approach E (`generated_at`) silently vanished (minor).** The spec recommends including it and the human explicitly flagged #7; the plan's settled list skips E and no phase mentions it. Include or explicitly defer.
