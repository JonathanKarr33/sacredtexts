## One thing worth a cheap follow-up

The `"n/a"` fix landed on the branch real pipeline output never produces. From the committed `summary.json`, an `_overall` cell is `{n, accuracy, expected_n, missing}` — `missing` is **always present**. So the spec's edge case in its real shape is `{n:0, accuracy:null, expected_n:100, missing:100}`, and `formatCell` (`localResults.ts:333`) checks `cell.missing` first and returns `"miss 100"` — not `"n/a"`. The branch now covered by tests (`missing` absent) only occurs in hand-written fixtures.

This isn't a crash and `"miss 100"` is arguably more informative, so I'm not blocking. But the agreed iteration-1 resolution was "the display must be `n/a`", and for real data it still isn't. A combined string (`n/a (miss 100)`) satisfies both, plus one test asserting the real-shaped cell.
