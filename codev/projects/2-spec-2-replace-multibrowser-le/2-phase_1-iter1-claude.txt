## Minor findings (non-blocking)

1. **Stale doc comment in `LocalResultsPage.tsx:9-13`** — still says "or if the fetch 404s — it renders the committed sample". That is no longer true; a 404 now surfaces a localized error. The comment contradicts the code in a file this phase changed.
2. **Malformed `summary.json` error is not localized.** `loadRun` line 280 does a bare `JSON.parse(s.text)`, so the `malformed` message is just `Unexpected token …` with no file/run. The JSONL path (`parseJsonl(…, "${base}/scores.jsonl")`) *is* localized with file + line. The spec's error scenario asks for "which run, which line"; one try/catch prefixing `${base}/summary.json` closes the gap.
3. **Test vacuity in `listRuns`' symlink assertion.** `expect(ids).not.toContain("escape")` passes because `Dirent.isDirectory()` is already false for a symlink — the `real !== root && !real.startsWith(root + sep)` branch at `runsEndpoint.ts:46` is unreachable for symlinked entries and has no covering test. Deleting that branch would break nothing. (The equivalent check in `resolveRunFile` **is** genuinely covered — `escape/secret.json` resolves through the symlink and is rejected by the containment check, so that one is real.) Side effect worth knowing: a legitimately symlinked run directory under `runs/` is silently skipped from the index.
4. **Roster path silently drops answers not in the roster.** In `joinResults`' roster branch, an `(question_id, model_id)` present in `answers.jsonl` but absent from `questions.jsonl` disappears from the output, and counts would then disagree with `summary` `n`. Fine while the roster is authoritative and co-produced, but there's no test or diagnostic for the stale-roster case.
5. **`parseSummary` normalizes absent `by_tradition` to `{}`** (pre-existing). The spec's edge case "run with `by_tradition` absent → section omitted gracefully" means Phase 3 must test emptiness, not truthiness. Flagging so it isn't a surprise later.
